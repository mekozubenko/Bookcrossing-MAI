# Буккроссинг МАИ

**Буккроссинг МАИ** — студенческий сервис для обмена книгами: можно найти книгу в каталоге, узнать место передачи и связаться с владельцем либо разместить собственное объявление.

> **Статус:** фронтенд находится в разработке и использует тестовые данные (моки). Интеграция с реальным API и верификация контактов требуют согласования и проверки с бэкендом.

## Возможности фронтенда

- Главная страница с описанием сервиса и последними объявлениями.
- Каталог книг с поиском по названию и автору, фильтрами по жанру и месту передачи.
- Страница отдельной книги с описанием, местом передачи и раскрытием контакта.
- Форма размещения книги с проверкой полей и выбором обложки (предпросмотр).
- Страница управления заявкой по секретной ссылке: сохранение изменений, отметка о передаче книги и удаление.
- Страницы политики обработки персональных данных и 404.

**Важно:** пока данные моковые, публикация, редактирование и удаление могут работать только в демонстрационном режиме. Выбор обложки пока не означает её загрузку на сервер.

## Локальный запуск фронтенда

**Требуется:** Node.js и npm (подходящую версию Node.js проверяйте по `frontend/package.json`, если там задано поле `engines`).

Из корня клонированного репозитория:

```bash
cd frontend
npm install
npm run dev
```

Vite выведет адрес локального сервера (обычно `http://localhost:5173/`).

Дополнительные команды:

```bash
npm run lint     # Проверка ESLint
npm run build    # Сборка для публикации
npm run preview  # Просмотр собранной версии
```

## Работа с API

Фронтенд пока может брать объявления из `src/mocks/listings.js`. Для подключения бэкенда предусмотрен `src/api.js`.

Предварительные группы запросов:

- `GET /api/listings` — список объявлений;
- `GET /api/listings/{id}` — отдельная книга;
- `GET /api/listings/{id}/contact` — контакт;
- `POST /api/listings` — создание;
- `GET`, `PATCH`, `DELETE /api/manage/{token}` — управление по секретной ссылке.

Названия полей, загрузка изображений и механизм верификации Telegram/телефона должны совпадать с актуальным контрактом бэкенда. Приведённые маршруты — целевой контракт, а не утверждение, что все запросы уже работают.

## Что ещё в работе

- Подключение реального API вместо моков.
- Подтверждение контактов и защита от публикаций с неподтверждёнными данными.
- Отправка обложек на сервер.
- Финальная адаптивность, тестирование и доработка интерфейса.

## Работа с Git

Разработку рекомендуется вести в отдельных ветках и отправлять изменения в `main` через Pull Request. Не коммитьте `node_modules/`, папки сборки, `.env` и локальные настройки IDE. Файл `package-lock.json` **нужно коммитить** для воспроизводимой установки зависимостей.
